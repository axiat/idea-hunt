# 原生上下文续接

## 工具与任务

主会话的 `resume` 恢复对话与运行档案。子角色能否续接，以当前原生工具 schema、调用回执和角色实际回应核验。总 Leader 保持运行根单写，现有任务、权限、来源耗用、拒绝和原件保持。

支持 `SendMessage` 的 Claude Code 环境通过原角色名或真实 agent ID 联系既有上下文。当前 `Agent` 没有 `resume` 参数时，其用途是创建新上下文；创建新 actor 不能代替原上下文续接。`ListAgents` 没有列出角色、`TaskStop` 返回 `No task found`、元数据 `finished=true` 和输出缓存目录变化，都不能单独判断消息路由是否可用。

## 原 ID 续接

1. 总 Leader 核对原 `task_id`、`agent_id`、有效任务引用、当前用户授权和已有续接记录。没有同一事件的待处理探测时，向原 ID 发送一次管理消息，例如：

   ```text
   仅确认原身份、原任务是否可见，以及显式已形成材料的位置。
   当前仅做 checkpoint；保持原权限与任务状态。
   已形成原件按实际许可保全，新科研推导和来源请求等待明确派发。
   ```

2. 原生工具返回 `queued` 或 `Resuming agent` 时，保存原回执并等待角色实际回应。同一请求未回应时保持一次在途探测；只有新证据或路由变化才重新判断。工具成功不构成角色收件、任务启动、物理停止或科研完成。
3. 实际回应须核对发送者、原任务与上下文。材料核对只读取显式原件和精确原生消息；内部思考不构成草稿。科学消息继续使用完整 `message_ref`、作者交付收据和实际组长的全文实读收据。输出缓存文件所在目录不代替原生消息位置；新增消息绑定须有实际原生发送者证据，并保留原绑定。
4. 总 Leader 分别记录原 API 中断、本次原生消息调用、角色回应及后续任务检查。仍为 `started`、没有登记逻辑终态的原任务，沿用同一 actor、任务、版本、原输入和剩余额度，通过当前 `entry` 检查后可继续原任务的缺段；启动事实和 runtime 绑定保持原值。同一任务与同一故障只安排一次有限缺段续接，再次失败时暂停该任务并保全。

原生调用中断与逻辑任务的 `failed` 终态分别记录。同一原任务的消息续接不创建 replacement，也不声明旧 runtime 已停止。已登记为 `failed` 或 `stopped` 的逻辑任务仍按正式恢复链处理；新任务或替代 actor 继续核验真实停止、恢复映射、拒绝及来源限制。替代 actor 的拒绝继承覆盖恢复链中每个 actor 的全部历史任务及其恢复祖先，无关 actor 的拒绝不扩散。单纯路由成功不能复活终态任务，不能解除暂停或增加动作额度。

## 一次性续接记录

总 Leader 在原根 `harness_control.same_task_continuations` 中，以 `<task_id>/<failure_id>` 为唯一键登记管理记录。登记前重新读取原根并按 CAS 提交；同键已登记时先核对原回执和结果，保持既有尝试，不重复发送科研续接消息。每项记录包含：

```json
{
  "task_id": "<原任务>",
  "failure_id": "<已保全的原生中断标识>",
  "agent_id": "<同一原生角色ID>",
  "task_ref": {"path": "<原envelope>", "sha256": "<原hash>"},
  "attempt": 1,
  "reserved_at": "<实际登记决策时刻，带时区>",
  "authorization_ref": {"path": "<当前人工授权原生记录>", "line": 1, "raw_line_sha256": "<原行hash>"},
  "incident_ref": {"path": "<原中断记录>", "sha256": "<原hash>"},
  "context_checkpoint_ref": {"path": "<原ID消息回执及实际角色回应>", "sha256": "<hash>"},
  "entry_receipt_ref": {"path": "<本次真实entry检查收据>", "sha256": "<hash>"}
}
```

`attempt=1` 记录一次有限续接的预留，不表示作者已经启动。实际消息发送、作者继续工作、完整正文及实读分别保存原生回执；同一故障再次失败时保持该项预留并暂停依赖工作。该管理记录不写入 `recoveries`，不增加自指 `recovery_of`，不覆盖原 `started_at`、`runtime_id` 或逻辑状态。

该字段由总 Leader 单写，不由只读校验器生成，也不独立授予动作权限。作者在实际继续前仍核对当前根和原任务并通过 `entry`；暂停、任务终态、原拒绝、额度耗用或输入变化均继续约束执行。记录不适用于逻辑终态恢复或替代 actor。

## 独立组与验收

故障暂停作用于相关任务及真实依赖。总 Leader 逐组核对原角色路由、已完成交付和当前任务条件，继续能够合法运行的组；未确认路由的组保持待核。G07 等单组故障不产生其他组的全局科研禁令。

原上下文确实不可寻址时，保存实际失败回执及缺失材料。替代执行须另外建立并验证显式接管与隔离方案，旧终态保持真实未知；尚未验证隔离的替代执行继续暂停。重复反馈或上下文压缩不能提供停止证据。同一反馈事项记录一次，达到工具上限后结束该反馈路径。

安装更新前比较实际任务引用的规范 hash。仅新增调用指引和诊断时，保留已引用的稳定规范原字节；需要改变规范或任务合同的修订按现有显式映射处理，旧 envelope 保持原文。

恢复验收逐项核对组长实际收件、作者实际开展工作、完整正文交付和同版本全文实读。`running` 标签、管理 ACK、工具成功和离线测试通过分别记录，均不能代替真实科研交付。
