# 机器人选题

## 研究条件与授权

研究方向默认以机器人为主，允许有明确机器人研究价值的相邻问题。实际条件由研究者填写，未知项保持未知：

- 团队人数与可投入时间：待确认。
- 可用算力及显存：待确认。
- 机器人、控制接口与采集条件：待确认。
- 可用数据、使用许可及预算：待确认。

每次显式启动或续跑时，先确认当前用户授权。普通研究涉及公开资料读取、已授权本地材料静态读取和必要 CPU 数学核对；GPU 训练或模型推理实验、机器人仿真或实机、独立后台服务及对外发布分别取得明确授权。设备可用不构成实验许可。用户当前的暂停或停止决定优先，暂停下仅保全材料，恢复须有新的明确人工授权。角色替换及规范变化均不能解除用户限制、工具拒绝或权限设置。

新运行材料写入选定研究工作区。引用的其他项目保持只读，修改由对应项目的明确授权管理。读取失败时记录原因与实际采用的来源，历史评审不构成学术新颖性证据。研究在当前活跃 CLI 会话内进行，关闭会话后的继续须显式续跑。

## 职责与写入

总 Leader 管理跨组主题、资源、进度、统一判据及目标核验；各组 Leader 负责完整科学材料、组内调度与档案。角色职责以 `角色/Leader.md`、`角色/组长.md`、`角色/调研人.md`、`角色/初筛人.md`、`角色/审稿人.md` 为准，科学判据以 `判定标准.md` 和 `评审校准.md` 为准。程序流程及通用任务、交付、来源预算和恢复规则统一执行 `idea-hunt` skill。

运行根 `状态.json` 仅由总 Leader 写入，写前比较已读取的原字节，冲突时重新读取并合并，执行 compare-and-swap。组档案与来源账分别由其 owner 写入；组长提交根任务登记、路由和状态变更请求。成员仅在角色许可内写入或以完整消息交付归档。组档案使用任务声明的 `<运行目录>/小组/<组号_主题>/`，已有文件保留并引用原位置。

科学全文由组长实际读取并确认交付，主会话仅接收简报；完成标签、消息回执和摘要仅作进度，不能证明实读或任务完成。需补充核验时由独立 agent 读取指定档案，总 Leader 保留结论与位置。三席原意见、版本与来源由组长保存，新独立达标审计仅读完整档案并返回结果及收据，总 Leader 核查达标清单。AI 裁决属于研究建议和任务调度，研究者确认问题、设计及最终科学结论。

复用角色须保留实际读域与作者身份，同作者多份材料仍属于同一作者。参与贡献创作的成员不能担任该候选的独立三席或达标审计，首轮独立意见完成后才交换评语。总 Leader 和组长的意见不替代正式票，人数与共识不替代证据。

## 保存与检索

运行中的来源、候选和裁决保存于任务指定组目录。已有调研、记录与历史索引保留原位置，新任务按需读取并引用；新工作区允许没有历史材料。

候选状态保存于内容或 frontmatter。科学全文优先使用简短完整的 Markdown 原件，JSON 保存引用、版本和任务事实。文件名保持可检索；正式文字使用完整陈述句，实质结论引用原论文、项目文档或代码；检索摘要仅作线索，可行性估计明确假设，未运行实验时明确标记。

本地检索按当前可用工具执行。读取外部下载材料的 Python 使用 `-I`；命令遵循当前用户环境的实际约束。
